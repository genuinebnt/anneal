# Rust prerequisites for the BusTub course

Generated by `tools/rust_prereqs.py`; edit the data there, not this file.

The owner has limited Rust knowledge, and the course gives creative freedom, so every module lists the practice from the **Rust tracks** worth doing first. Tracks that are written already are marked **written**; the rest are **planned** and are implemented *after* the course, in the order of [section 3](#3-the-order-to-write-the-tracks-in) (the order the course first needs them). Stage pages already link every track as `/t/<slug>`, planned or not, so nothing needs linking again when a track is written: **name the track's directory under `content/tracks/` exactly its slug**, and add its stages and problems. Until then a planned link lands on a "planned" page (`web/src/trackSlugs.ts`).

## 4. Gaps the tracks do not cover yet

Things the course asks for that no planned track has a stage for; decide whether to add a stage to an existing track (recommended) or leave them to the optional concept articles:

- **Reading compiler errors** (borrow, move, `Send`): L2 and L1 teach the rules; a stage that is nothing but "read this error and fix it" would serve every module. Today the concept `reading-compiler-errors` covers it.
- **Byte-level work** (`from_le_bytes`, `copy_within`, `chunks_exact`, `try_into`): S3 covers slices and F7 encodings; a short stage "bytes and endianness" in S3 would make 2a smoother.
- **Drop and RAII guards**: spread across L1 (clones & drops), S8 (Drop order) and S7 (Deref); a guard-focused stage in S8 ("RAII guards") would serve 1a and 1g.
- **Property testing with a model**: Y5 lists proptest; the course uses it from 1a, so Y5's first stage needs a model-test problem that appears early.
- **Timeouts and hang-proof tests** (a `recv_timeout` helper): worth one Y5 problem; used from 1b.
